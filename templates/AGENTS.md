# AGENTS.md — this repo is guarded by PSX Repotector ⬡

Any AI working here MUST handshake first. This repo ships a portable guardian that
knows what already exists and what will break. Use it — do not fly blind.

## On arrival (required)

1. Run the handshake:
   ```
   npx psx-repotector handshake
   ```
   It prints the repo map, the ground rules, a live quality gate, and a passport.

2. Wire the MCP server into your client so you can call the gates as tools:
   ```
   npx psx-repotector mcp        # stdio MCP server
   ```

## The three gates — use them BEFORE you act

- **REUSE — `find_existing({ intent })`**: search the Atlas before building anything.
  If it already exists, extend it. Do not rebuild what is already here.
- **PROTECT — `blast_radius({ changedFiles? })`**: before editing, see the transitive
  dependents plus impacted routes and components. Do not break them.
- **INTEGRATE — `canon_check({ changedFiles? })`**: follow the repo's established
  patterns. Fix violations before proposing the change.
- **`atlas_query({ query })`**: ask the map about structure instead of guessing.
- **`quality_gates()`**: line-budget, structure, and secret-hygiene proof.

## Hard rules

- Do NOT rebuild what exists — `find_existing` first.
- Do NOT break what exists — `blast_radius` first.
- Follow the patterns — `canon_check`.
- Keep every source file under 300 lines.
- Never commit real secrets or a tracked non-example `.env`.

State (`.repotector/atlas.json`, `intent.json`, `dna.json`, `proof.json`) is generated by
`npx psx-repotector init`. If a tool says state is missing, run init.
