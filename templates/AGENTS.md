# AGENTS.md — this repo is guarded by PSX Repotector ⬡

**STOP. Before you read, build, or edit anything here, you must handshake.**
This repo ships a portable guardian (an MCP info-point) that knows what already
exists, what will break, and what is still missing. Every AI that crosses this
door is logged in a visitor register. Do not fly blind, and do not skip the door.

## On arrival — MANDATORY, in order

1. **Handshake and say who you are.** This logs your entry and hands you the
   ground rules, the live quality gate, the city-map, and a passport:
   ```
   npx psx-repotector handshake          # CLI, or call the `handshake` MCP tool
   ```
   Via MCP, call `handshake({ who, model?, purpose? })` — `who` is required
   (e.g. `"claude-code@dir"`). No deep tool will answer until you have handshaked.

2. **Wire the MCP server** so you can call the guardian as tools:
   ```
   npx psx-repotector mcp                # stdio MCP server (handshake-first)
   ```

3. **If the repo is locked**, present the passphrase once per session:
   ```
   unlock({ passphrase })                # only if the operator enabled a lock
   ```
   The lock is OPTIONAL and per-repo. The handshake is never locked; the deep
   map (atlas/blast/dna/city-map) may be.

4. **Read the city map** to see what is built vs missing before you plan:
   ```
   city_map()                            # DNA intent, brain pointers, built-vs-missing
   ```

5. **When you leave, sign out** with a one-line summary so the log stays complete:
   ```
   depart({ summary })
   ```

## The tools — use them BEFORE you act

- **`handshake({ who })`** — front door. Mandatory first call; logs your entry.
- **`city_map()`** — the info-point: what the DNA specified, what the Atlas shows
  is built, what is MISSING, and pointers to Genome/Phenome when present.
- **`register({ limit? })`** — who has entered/left and who is inside right now.
- **REUSE — `find_existing({ intent })`** — search the Atlas before building. If it
  exists, extend it. Do not rebuild what is already here.
- **PROTECT — `blast_radius({ changedFiles? })`** — before editing, see the transitive
  dependents plus impacted routes and components. Do not break them.
- **INTEGRATE — `canon_check({ changedFiles? })`** — follow the repo's established
  patterns. Fix violations before proposing the change.
- **`atlas_query({ query })`** — ask the map about structure instead of guessing.
- **`quality_gates()`** — line-budget, structure, and secret-hygiene proof.
- **`unlock({ passphrase })` / `depart({ summary })`** — session lock + sign-out.

## Hard rules — the PSX standard

- Handshake first, and declare who you are. Every crossing is logged.
- Do NOT rebuild what exists — `find_existing` / `city_map` first.
- Do NOT break what exists — `blast_radius` first.
- Do NOT add a parallel wiring next to an existing one — `atlas_query` first.
- Follow the patterns — `canon_check`.
- Keep every source file under the line budget (default 300 lines).
- Never commit real secrets or a tracked non-example `.env`.
- Sign out with `depart` when you finish, summarizing what you changed.

State (`.repotector/atlas.json`, `intent.json`, `dna.json`, `proof.json`,
`register.jsonl`, `policy.json`) is generated by `npx psx-repotector init`.
If a tool says state is missing, run init. The Atlas/DNA refresh on `init` and,
inside a PSX Workbench project, on every "Sync truth".
